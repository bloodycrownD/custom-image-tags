# WinUI 成对比较标注器 PRD

## 背景

父级需求 [model-training PRD](iteration/model-training/prd.md) 已将**成对比较（Pairwise）**确立为核心训练数据采集方式，验收项 F2 要求：用户能通过界面完成「A vs B 更喜欢哪张」及「差不多（Tie）」，并将结果持久化且**每条记录保留双端作者 ID**（允许跨作者比较）。

当前缺口：

- 训练脚本侧可消费成对比较数据，但**没有**面向用户的采集工具。
- 历史三分类（good/keep/trash）可通过批处理转为种子 pair，该能力规划在 **classify 侧 CLI**，**不在本迭代范围**。
- 全量 O(n²) 成对扫不现实；标注侧采用**固定规模随机分片 + 组内智能队列**控制比较次数，**不要求**组间人工合并全序。
- 仓库 `simple_viewer`（WinUI 3 master）在其技术底座上**单独分支**交付 **`annotator.exe`**，不并入日常看图 master。

用户已明确：**一步到位 WinUI**（Fluent）；落盘格式 **`pairs.json`**；配对策略为**正式队列能力**（非 MVP 随机对）。

## 目标（含成功指标）

### 业务目标

1. **满足 model-training F2**：高效完成 A/B/Tie 标注，支持同作者与跨作者比较。
2. **控制标注量**：通过分片与组内队列，避免 O(n²) 全扫；单组规模有上限。
3. **数据可直接训练**：`pairs.json` 可供 `train_rank` 消费（或经一次性转换）。
4. **与看图器解耦**：独立分支 / `annotator.exe`。

### 成功指标（可量化）

| 指标 | 目标值 | 测量方式 |
|------|--------|----------|
| 单次比较操作耗时 | ≤ 5 秒 | 试跑 20 对计时 |
| 单轮连续标注 | ≥ 30 分钟无明显挫败 | 主观反馈 |
| 落盘完整性 | 100% 含 `author_a`、`author_b`、路径、prefer | 抽检 `pairs.json` |
| 单组规模上限 | 可配置（如 15～30 张/组），且生效 | 配置与运行检查 |
| 真人标注冷启动 | ≥500 对（与 model-training 对齐） | 计数 |
| 界面满意度 | ≥ 4/5 | 主观评分 |

## 用户与场景

### 使用场景

- **场景 1：分片标注**——打开数据集根目录，系统将全部图片划入多个**固定规模随机小组**（可选分层随机以保证作者覆盖）；用户在**当前组内**按队列给出的 A/B 对进行比较。
- **场景 2：跨作者自然发生**——组内混有不同作者图片时，比较可跨作者；落盘仍记录双端 `author_id`。
- **场景 3：增量补标**——追加写入 `pairs.json`（或按组分文件），不覆盖历史。
- **场景 4：竖图并排**——保持宽高比，便于对比。

### 不包含（本迭代）

- classify 侧种子 pair / 校验 CLI。
- 模型主动学习选题（后续与 model-training 联动）。
- 组间人工合并排序或全局 5000 图单链全序标注。
- 合并入 Simple Viewer master。

## 范围

### 包含范围

1. **独立 WinUI 应用**
   - 分支如 `pairwise-annotator`；发布物 **`annotator.exe`**。
   - 复用 simple_viewer 的图片枚举、按视口解码等；UI 以**双图对比**为主。

2. **核心交互**
   - A/B/Tie；键盘快捷键；可跳过本对。
   - 状态区：当前**组编号**、组内进度、本会话已标对数、当前两张图各自作者 ID。

3. **标注分片（随机小组）**
   - 将库内图片划分为多个**固定上限规模**的小组；划分方式为**随机**（可选**分层随机**：控制每作者在各组最低出现次数，具体规则在 spec 定）。
   - **不要求**按作者 ID 作为分片边界；分片是**标注工作流**策略，与训练损失形式解耦。
   - 组与组之间**无需**人工合并；全局偏序由训练模型从稀疏边推断。

4. **组内比较队列（非 MVP 随机）**
   - 由算法生成「下一对」图片，默认采用**插入式排序比较**（新图在当前组偏序中二分定位）或等价的**稀疏有序构建**；可在组内达到可控比较量（约 O(k log k)/组，k 为组大小）。
   - 不要求组内完成完美全序即可结束该组；可配置组内**最少/目标比较条数**（spec 定默认值）。
   - 后续可扩展：模型不确定度插队（不在本迭代）。

5. **落盘：`pairs.json`**
   - 每条记录至少包含：`image_a`、`image_b`、`author_a`、`author_b`、`prefer`（`a` | `b` | `tie`）、`group_id`（可选）、`timestamp`（可选）。
   - 支持增量 append；崩溃不丢已提交记录。
   - 训练侧可读或经 classify 工具转换为历史格式。

6. **启动**
   - 选择数据集根目录（`author_id` 子目录 + 图片文件）；自动分片并进入第一组或续标未完成组。

### 不包含范围

1. 种子 / 校验 CLI（classify 另做）。
2. 主动学习队列（model-training 后续）。
3. 三分类移动文件夹标注。
4. 本 PRD 不含技术 spec。

## 核心需求

### 需求 1：双图成对比较界面

同屏对比；竖图不拉伸变形。

### 需求 2：A / B / Tie 与快捷键

三种判定 + 跳过；优先键盘操作。

### 需求 3：随机分片 + 组内队列

固定规模随机（或分层随机）分片；组内由**插入式/稀疏有序**队列出题，禁止无脑全对枚举。

### 需求 4：`pairs.json` 与双端作者

每条比较保留双端 `author_id`；允许 `author_a ≠ author_b`；增量落盘。

### 需求 5：与训练衔接

输出须被 model-training / `train_rank` 消费；本工具不负责训练。

### 需求 6：独立 `annotator.exe`

不合并 simple_viewer master。

## 验收标准

| 编号 | 验收项 | 通过标准 |
|------|--------|----------|
| A1 | 双图展示 | 竖图同屏、无明显拉伸 |
| A2 | A/B/Tie | 各 5 次成功写入 |
| A3 | 双端 author | `pairs.json` 中 `author_a`/`author_b` 正确 |
| A4 | 跨作者 | 至少 1 条 `author_a ≠ author_b` 且训练可读 |
| A5 | 分片上限 | 单组图片数 ≤ 配置上限 |
| A6 | 队列非纯随机 | 同组内连续两对存在队列逻辑关联（非独立均匀随机对） |
| A7 | 增量落盘 | 杀进程后已标记录仍在 |
| A8 | 训练可读 | classify 训练准备流程无解析错误 |
| A9 | 快捷键 | 可无鼠标完成一轮 A/B/Tie |

体验：连续 30 分钟可用；主观 ≥4/5。

## 风险与待确认项

| 风险 | 缓解 |
|------|------|
| 纯随机分片致某作者无边 | 可选分层随机 |
| 组内插入比较疲劳 | 组规模上限 + 组内目标条数 cap |
| `pairs.json` 与旧 `viewer.sort` | classify 侧 convert 脚本 |

**待确认（spec）**：组大小默认 k、组内目标比较条数、单文件 vs 每组建 `pairs.json`。
