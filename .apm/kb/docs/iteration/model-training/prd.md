# 二次元图片个性化审美评分系统 PRD

## 背景

用户拥有约 5000 张二次元图片（1000×2000 像素左右），涵盖约 700 位作者，每位作者的图片数量分布不均，同一作者的不同画风图片数量也不均。当前用户需要从这些图片中筛选出符合个人口味的作品，但逐张人工评估耗时巨大（约 14 小时/5000 张）。

用户对不同画风/作者的图片评判标准不同，偏好并非全局一致的函数。同时，用户的审美偏好在中间区域（40~60 分）具有模糊性和情境依赖性——人类自身对「还行」的图片难以稳定评分，但对极端优秀（90~100 分）和极端糟糕（0~10 分，如广告、低质涂鸦）的图片具有高度一致的判断力。

因此，需要构建一个能够理解用户个性化审美、优先保障极端判断准确性、并在不确定区域主动寻求人工复核的智能评分系统。系统应能随用户偏好演化持续优化，最终将人工评估工作量降低 80% 以上。

### 与历史探索的关系

项目在模型训练侧已历经一轮有效探索，结论应写入本需求而非推倒重来：

| 阶段 | 探索内容 | 对本需求的启示 |
|------|----------|----------------|
| 三分类（good / keep / trash） | 验证「图片 + 作者 ID」、竖图预处理、训练工程（验证集、早停等） | **保留**作者维度与数据组织方式；**不再**以三分类作为训练目标 |
| 成对比较（Pairwise） | 验证「A vs B 更喜欢哪张」及「差不多」的标注与训练可行性 | **确立**为核心训练数据采集与学习目标 |
| 结合二者 | 历史三分类可映射为业务语义上的极端与中间区，并转为种子比较关系 | **冷启动**用，后续由真人成对比较逐步替代 |

**为何放弃三分类作为训练目标：**

1. **标注成本高**：每张图需归入一类，二次校验等价于重新分类；中间类（keep）尤其难以稳定标注。
2. **与认知不匹配**：用户对「哪张更好」的判断天然强于「这张是 keep 还是 good」。
3. **中间区被错误离散化**：keep 内混有不同偏好强度，强行单标签与「中间区域允许模糊」矛盾。
4. **迭代不友好**：偏好变化时需大量重标绝对标签；成对比较只需补充局部 pair。

**范式转变（业务层表述）：**

- **训练阶段**：以**稀疏成对比较**为监督信号（更喜欢 A / B / 差不多）；**不要求**全库 O(n²) 全对枚举，也**不要求**人工构建全局全序。模型从部分边学习**相对偏好**并输出连续偏好分。
- **标注分片（与训练解耦）**：annotator 采用**固定规模随机小组**（可选分层随机）组织标注会话；组内由队列算法出题（如插入式比较）。组内可自然出现**跨作者**比较；**不要求**按作者 ID 分片，**不要求**组间人工合并排序。
- **落盘**：比较记录写入 **`pairs.json`**（含双端 `author_id`），由 `annotator.exe` 产出；训练侧读取稀疏边集合即可。
- **展示阶段**：极端低分、极端高分、待复核中间区由偏好分排序与阈值/分位数切分呈现——对应历史上 trash / good / keep 的**业务语义**，但**不是**训练时的硬分类标签。
- **历史标注**：已有 good / keep / trash 目录结构可转换为种子 pair，仅作冷启动，不作为持续标注方式。

**标注复杂度（业务认知，非实现承诺）：**

- **不要求全局全序**：推理阶段的全库排序由模型从稀疏边推断；人工不必、也无法扫完 O(n²) 对。
- **与 O(n) 三分类的区别**：每张图打一档（好/中/差）虽为 O(n) 次标注，但需「归类」思考，中间档不稳；**稀疏成对比较**可在相近标注量下（固定总预算或每图少量比较）用直觉完成，故以 pairwise 为主路径。
- **条件变量与标注分片解耦**：annotator 的随机小组只服务于出题与控量；训练侧用于 Embedding 的「组」可按作者样本量另行聚合（见需求 1），二者不必同一划分。

**图片输入约束（业务体验）：**

- 竖图（约 1000×2000）须**保持宽高比**，避免拉伸变形；优先采用等比缩放后填充为正方形输入，而非裁剪（裁剪易损失构图信息）。
- 填充区域颜色应统一、且训练与推理一致（对插画内容，深色填充通常优于浅色衬底带来的视觉干扰）。

本需求专注于**业务能力与产品交互**，不涉及具体模型结构、损失函数、接口与库表等技术实现细节。

## 目标（含成功指标）

### 业务目标

1. **降低人工评估成本**：将用户从「逐张看 5000 张图」中解放出来，通过模型辅助筛选，将必须人工精看的图片数量降至 1000 张以内。
2. **保障极端判断质量**：系统对「垃圾图片」（0~10 分）和「完美图片」（90~100 分）的判断准确率需显著高于随机，错误率控制在 5% 以内。
3. **识别不确定区域**：系统应能主动标记「不确定」的图片（即中间区域），交由用户复核，避免模型在模糊区域强行做出错误判断。
4. **支持偏好演化**：模型能够随着用户持续使用（新成对比较、新偏好反馈）逐步适应口味变化，而不是一次性训练后固化。

### 成功指标（可量化）

| 指标 | 目标值 | 测量方式 |
|------|--------|----------|
| 人工复核图片占比 | ≤ 20%（1000 张/5000 张） | 系统日志统计 |
| 极端区域（0~10, 90~100）准确率 | ≥ 95% | 用户验收抽检 |
| 极端区域召回率（垃圾图片被检出比例） | ≥ 90% | 用户验收抽检 |
| 中间区域误差容忍度 | ±15 分（30~70 分区间） | 模型与用户主观排序/分档对比 |
| 用户满意度 | 4.5/5 分 | 用户主观反馈 |
| 模型迭代效率 | 每轮新增 200 条成对比较即可见提升 | 训练曲线与排序质量监控 |

## 用户与场景

### 目标用户

- **主要用户**：二次元图片收藏者、同人画作爱好者，拥有较大规模的个人图片库，对图片质量有明确的个人偏好标准（画风、构图、色彩、内容主题等）。

### 使用场景

- **场景 A：批量入库筛选**——用户下载了一批新图片（如 1000 张），需要快速判断哪些值得保留、哪些是垃圾。
- **场景 B：已有图库排序与整理**——用户想对 5000 张存量图片按个人喜好排序，以便后续浏览或导出。
- **场景 C：偏好漂移适应**——用户审美发生明显变化（如从萌系转向写实系），系统需要重新适应新偏好。
- **场景 D：轻量标注迭代**——用户通过「两张图选更喜欢哪张」补充标注，无需对单张图反复打三分类标签。

### 用户画像

- 熟悉二次元文化，对不同画风（萌系、写实、赛璐璐、厚涂等）有辨识力。
- 对「垃圾图片」的定义明确：如带有广告水印、低分辨率涂鸦、画面严重崩坏、内容无关等。
- 对「完美图片」的定义：构图、色彩、角色表现力、作者技法均达到个人偏好天花板。
- 对中间区域的图片难以稳定打分（如「还行，但说不上哪里好」），愿意接受模型的不确定性输出，并可通过「差不多」表达 Tie。

## 范围

### 包含范围

1. **图片特征提取与作者信息建模**
   - 支持输入图片（1000×2000 像素左右）并提取视觉特征。
   - 支持作者 ID 作为辅助特征，以捕捉「不同作者不同标准」及「整体更偏好某作者」；须能应对**作者图片过多/过少**（见需求 1 与风险节）。
   - 同一作者的不同画风图片应能通过视觉特征区分；**成对比较允许跨作者**，每条监督须保留双端 `author_id`。

2. **个性化偏好评分模型**
   - 模型应输出 0~100 的连续偏好分（由相对偏好学习推导），核心优化目标是极端的 0~10 分（垃圾）和 90~100 分（完美），而非全局均等优化。
   - 模型应同时输出**不确定性估计**，明确告诉用户「这张图我拿不准」。

3. **偏好数据采集方式**
   - **核心**：「A vs B 更喜欢哪张」的成对比较（pairwise），支持 Tie；由 **`annotator.exe`** 采集，落盘 **`pairs.json`**。
   - **稀疏即可**：标注预算是有限条边（如初始 ≤1000 对），**不要求**稠密排序或全对覆盖；组内队列旨在高效产生信息量，而非完成组间全序。
   - **分片**：随机（或分层随机）固定规模小组，属标注工具策略，不约束训练损失形式。
   - **辅助**：单张 0~100 分（可选，非主路径）。
   - **冷启动**：good / keep / trash → 种子 pair。
   - 不确定图片复核可采用成对比较或确认/否决。

4. **主动采样与效率优化**
   - 系统应主动选择「信息量最大」的图片对供用户比较，而非随机采样。
   - 系统应优先让用户复核模型认为「不确定」的图片。

5. **模型迭代与持续学习**
   - 支持用户新增成对比较后增量更新模型。
   - 支持检测用户偏好漂移并触发重新校准。

6. **结果输出与可视化**
   - 按偏好分排序展示全部图片（高→低 / 低→高可切换）。
   - 标记「垃圾图片」（0~10 分）和「完美图片」（90~100 分）两个极端集合（**展示层切分，非三分类训练**）。
   - 标记「待复核」图片（不确定性高的中间区域）。

### 不包含范围

1. 不支持多模态输入（如文本标签、画师风格描述）。
2. 不支持图片自动分类/打标签（如按角色、主题、色系归类）——本需求仅关注评分排序。
3. **不再要求**用户以 good / keep / trash 三分类作为常规训练标注方式。
4. 不支持多用户协同评分或社交分享。
5. 不提供图片存储、管理、去重功能——仅关注评分能力。
6. 不包含图像增强、超分辨率、格式转换等图像处理功能。
7. 不包含自动化爬取或下载图片的能力。

## 核心需求（3-7 条）

### 需求 1：支持多维度特征输入（图片 + 条件组）

**描述**：训练与推理使用图片视觉特征 + **条件组标识**（用于表达「在什么标准/语境下评判」）。`pairs.json` 中**保留真实 author_id** 备查与再聚合；送入模型的可以是原始 author，也可在预处理阶段映射为 **train_group_id**（按作者作品数量等规则聚合：样本过少合并为虚拟组、样本过多可拆分或降权，具体阈值在 spec 调参）。

**目的**：区分「图本身质量」与「对该作者/画风整体的偏好」；跨作者比较边需要条件维；缓解 700 作者分布极不均带来的 Embedding 不稳或过拟合。

**理由**：条件维要的是统计上稳定的「组」，不一定是真实画师 ID。历史 demo2 的作者 Embedding 方向可延续，但是否直接用 author_id、是否改为 train_group_id，以 spec 中对照实验为准（见待确认项）。

---

### 需求 2：基于稀疏成对比较（Pairwise）的偏好学习（核心训练范式）

**描述**：核心监督来自「两张图更喜欢哪张」及 Tie；**不以**三分类为常规标注。允许**稀疏**边集（远少于 n(n−1)/2）；学习算法须能从部分比较推断全局可用排序/打分，**不要求**人工给出完整排序。采集由 `annotator.exe` + 组内队列完成。

**理由**：成对比较符合人类判断；稀疏监督在推荐/排序领域成熟（Learning to Rank）。全对枚举不现实且非必要。

---

### 需求 3：历史三分类冷启动（种子 pair，非持续标注）

**描述**：用户已有的 good / keep / trash 历史标注，系统应能转换为种子成对关系用于初始训练（例如：good 优于 keep、keep 优于 trash、good 优于 trash；同档 keep 之间可为 Tie）。该数据仅作冷启动，后续迭代以真人成对比较覆盖。

**理由**：避免浪费已有标注投入，同时明确其权重应随新 pairwise 数据增加而降低，防止旧绝对标签噪声固化。

---

### 需求 4：非对称关注极端区域

**描述**：模型优化与效果评估应非对称地优先保障极端区域（0~10 分与 90~100 分）的判断质量；中间区域（30~70 分）允许更大误差。极端集合在结果层通过偏好分阈值/分位数切分呈现，对应历史上 trash / good 的业务语义。

**理由**：用户对极端图片判断力最稳定；中间区域人类自身也难以稳定打分，不应强迫模型或用户给出虚假精确标签。

---

### 需求 5：输出不确定性估计

**描述**：模型除了输出 0~100 的偏好分外，还应输出该评分的不确定性，用于标识「模型不确定的图片」。系统应优先将不确定性高的图片推送给用户复核。

**理由**：在中间区域，强行输出精确分数不如主动承认不确定，将决策权交还用户。

---

### 需求 6：主动学习驱动的样本采集

**描述**：系统在每次迭代中，应优先选择当前模型「最不确定」的图片对或单张图片，供用户标注/比较，而非随机采样。

**理由**：用户希望用最少的标注次数达到最佳效果；主动学习可提升标注效率。

---

### 需求 7：偏好演化、增量更新与结果复核工作流

**描述**：模型应支持随用户新增成对比较增量更新；能检测偏好漂移并提示重校准。结果展示须包含：全量排序、极端集合聚合、待复核标记，并引导用户对不确定结果进行复核。

**理由**：审美会随时间变化；最终决策权在用户手中，系统应降低发现错判与不确定的成本。

## 验收标准

### 功能验收

| 编号 | 验收项 | 验收方法 | 通过标准 |
|------|--------|----------|----------|
| F1 | 模型支持图片 + 条件组双输入 | 运行推理，检查输入 | 能同时接受图片与 author/train_group 条件，输出不报错 |
| F2 | 成对比较数据采集与持久化 | `annotator.exe` 完成 A/B/Tie | 写入 `pairs.json`，含双端 `author_id`，允许跨作者 |
| F3 | 历史三分类可转为种子 pair | 对含 good/keep/trash 的数据执行转换 | 生成可用种子 pair，且不与新 pairwise 采集冲突 |
| F4 | 模型输出偏好分 + 不确定性 | 运行推理，检查输出格式 | 含 0~100 偏好分及不确定性数值 |
| F5 | 极端区域效果优于中间区域 | 分区域抽检排序/分档一致性 | 极端区用户认可度显著高于中间区 |
| F6 | 主动采样优先不确定样本 | 检查采样队列 | 不确定性高的样本/图片对优先出现 |
| F7 | 支持增量更新 | 新增 ≥100 条成对比较后更新 | 更新时间明显短于全量重训，排序质量有提升 |
| F8 | 结果展示：排序、极端集合、待复核 | UI 或报告检查 | 三项功能可用且与偏好分/不确定性一致 |
| F9 | 竖图输入不变形 | 抽检预处理前后构图 | 无拉伸；等比缩放 + 填充策略一致应用于训练与推理 |

### 效果验收

| 编号 | 验收项 | 验收方法 | 通过标准 |
|------|--------|----------|----------|
| E1 | 人工复核图片占比 | 完整批次（如 5000 张）运行后统计复核量 | 复核 ≤ 1000 张（≤20%） |
| E2 | 极端区域准确率 | 抽检模型标记为极低分与极高分各 50 张 | 准确率 ≥ 95% |
| E3 | 极端区域召回率 | 用户标出全部「垃圾」对比模型检出 | 召回率 ≥ 90% |
| E4 | 中间区域容忍度 | 100 张中间区图片对比用户主观分档 | 误差在约定容忍内（如 ±15 分等效） |
| E5 | 用户满意度 | 主观评分 1~5 | ≥ 4.5 分 |
| E6 | 标注负担 | 统计完成冷启动后维持效果所需新标注量 | 以成对比较为主，无需恢复三分类逐张标注 |

### 验收流程

1. **准备阶段**：图片按作者整理；确认是否存在 good/keep/trash 历史标注。
2. **冷启动**：将历史标注转为种子 pair，并补充 ≥500 次真人成对比较（或等价排序关系）。
3. **初始训练**：得到可排序、可输出不确定性的初始模型。
4. **迭代标注**：至少 3 轮主动学习（每轮约 200 次比较 + 适量复核）。
5. **最终评估**：执行 F1~F9、E1~E6，记录结果并完成满意度评价。

## 约束与依赖

### 约束

- 数据集规模：约 5000 张图片，700 位作者，分布不均。
- 图片尺寸：约 1000×2000 像素竖图为主；预处理须保持构图，避免裁剪导致信息丢失。
- 用户时间预算：初始阶段总标注量 ≤ 1000 次比较/复核（含种子 pair 转换后的少量确认）。
- 偏好主观：无客观唯一正确答案，以用户个人判断为准。
- **标注范式约束**：新增标注以成对比较为主，不回流为三分类强制标注流程。

### 依赖

- 图片按作者 ID 组织；成对比较数据需可关联作者。
- 若存在历史 good/keep/trash，需可读取并转换为种子 pair。
- 用户具备完成初始成对比较标注的意愿。
- 模型训练与推理需可用计算资源（细节在技术 spec 中评估）。

## 风险与待确认项

### 风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 种子 pair 携带旧三分类噪声 | 初始排序偏差 | 限制种子权重，尽快用真人 pairwise 覆盖 |
| 用户标注不一致 | 模型学到噪声 | 以成对比较为主；Tie 表达中间模糊 |
| 作者多、人均图片少 | 条件 Embedding 过拟合 / 冷门无效 | train_group 聚合（冷门合并虚拟组）、低维、正则、采样平衡；A/B：无条件 / author / train_group |
| 单作者作品过多 | 单一向量记住大盘 | 拆分为多 train_group、训练降采样或更强图像侧（spec） |
| 稀疏标注覆盖不均 | 部分图无边、排序不稳 | 主动学习补边；种子 pair；组内队列 + 分层随机 |
| 随机分片致某作者无边 | 学不到该作者偏好 | 分层随机；训练时按作者加权 |
| 偏好漂移过快 | 输出脱节 | 增量更新 + 定期验证触发重校准 |
| 不确定性估计不准 | 复核队列质量差 | 校准与抽检（技术 spec） |
| 标注疲劳 | 后期数据质量下降 | 每轮 ≤200 次比较，进度可视化 |

### 待确认项

1. **「垃圾图片」边界**：是否包含「内容不相关」（如风景照混入）？还是仅限低质量？
2. **复核工作流**：模型自动应用判断（仅复核不确定部分），还是先建议、用户确认后再应用？
3. **模型更新频率**：每次新增标注后自动更新，还是用户手动触发？
4. **Tie（差不多）的使用频率**：是否鼓励用户对接近的图片主动标 Tie，以减少虚假精确排序？
5. **条件 Embedding 形态**：v1 默认保留条件维；对照实验：无 / 原始 author_id / train_group_id 聚合，以极端区指标选型。
6. **随机分片组大小 k 与组内目标比较条数**：与总标注预算 ≤1000 的对齐（annotator spec）。

## 附录：术语表

| 术语 | 定义 |
|------|------|
| 成对比较（Pairwise） | 同时展示两张图片，用户选择更喜欢哪一张，或「差不多」 |
| 标注分片 | 将图库划分为固定规模随机小组以限制单 session 比较量；与训练损失解耦 |
| pairs.json | annotator 落盘的比较记录；含双端 author_id，允许跨作者 |
| annotator.exe | WinUI 成对标注独立应用（simple_viewer 分支） |
| train_group_id | 训练用条件组标识；由 author 等规则聚合得到，可与标注分片无关 |
| 种子 pair | 由历史 good/keep/trash 等绝对标注自动推导的初始比较关系，仅用于冷启动 |
| 偏好分 | 模型对单张图输出的 0~100 连续分数，用于排序与切分极端区 |
| 极端区域 | 偏好分对应 0~10（垃圾）和 90~100（完美）的图片集合（展示层概念） |
| 中间区域 | 偏好分约 30~70 的图片集合，人类与模型均可能不稳定 |
| 不确定性估计 | 模型对偏好分置信度的量化输出 |
| 主动学习 | 优先选择信息量大的样本供用户标注 |
| 偏好漂移 | 用户审美偏好随时间显著变化 |
| 增量更新 | 用新成对比较更新模型，无需每次全量重训 |
| good / keep / trash（历史） | 已废弃的**训练用**三分类标签；业务语义分别对应高偏好、中间模糊、低偏好，现通过偏好分排序与阈值呈现 |
