abstract: 用户问"低像素能否计算并打标"。分析发现根因：448 预处理销毁了原始分辨率信息，模型对低像素结构性失明。实现元数据特征通道（resolution/sharpness/compression 4 维接入头部，缓存 v2+开关）后受控实验（3 种子×开关 A/B + 诚实的折外 OOF 评估）给出决定性负面结论：低像素的模型输出折外 AUC≈0.49/0.51（等于瞎猜，此前 AP 0.1~0.4 全是小样本噪声、0.92 是记忆污染）；元数据 4 特征两次数独确认 AUC≈0.75（可计算上限）；堆叠零增量。7% 基率下 AUC 0.75 的高精度预填只能捞 ~15% 正例且误报远超收益 → 元数据特征默认关闭、低像素维持人工标注。通道保留待数据规模变化时重评。

assistant:
分析→实现→证伪的完整记录：
- **分析**（755 张、54 个低像素正例）：分辨率 AUC 0.70、清晰度 0.67、压缩率反向 0.32——单指标弱相关，固定规则精确率仅 13~23%；**根因：448 预处理把原始分辨率销毁，模型对尺寸结构性失明**。元数据 + 逻辑回归 5 折 CV 上限 AUC 0.75。
- **实现**：元数据 4 维（log像素/log短边/log1p清晰度/字节像素）接入头部——TagModel extra_features、features.py 缓存 v2（含归一化统计）、train/checkpoint meta（meta_dim/meta_norm）、tags_predict 推理侧同口径归一化、`use_meta_features` 开关（config + `--no-meta-features`）、3 个新单测。
- **受控实验**（3 种子 × 开关，头训练秒级用缓存）：mAP 0.6861 vs 0.6868（持平）；低像素 AP 0.26 vs 0.28（反而略降），种子间 0.16~0.37 狂摆（val support 3~7 纯噪声）。
- **决定性 OOF**（5 折重训头、只预测未见折，两划分种子）：模型低像素概率 AUC **0.487/0.512 = 等于瞎猜**；元数据 AUC **0.749/0.751**（两次数独确认）；堆叠 0.749/0.751 零增量。此前"0.92 CV"是训练集记忆污染，"AP 0.39"是小样本运气。
- **拍板**：元数据特征默认关闭（通道保留、开关可控；configs/tags_v0.yaml 注明原因），生产 checkpoint 重训为 meta_dim=0；低像素维持人工标注——7% 基率下 AUC 0.75 的高精度预填每捞对 1 张要搭 2~3 张错的，得不偿失。若用户愿意把低像素改成机械定义（如短边<800）则 100% 可计算，待用户拍板。
- 测试 84 全绿；缓存格式 v2（含 meta 字段，关闭时代码仍计算但训练不使用）。
